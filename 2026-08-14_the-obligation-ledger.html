Narracode · working paper

The Obligation Ledger

A week of trying to measure what a reader is still holding — the method, step by step, what it found in three unpublished stories, and the uncomfortable place it leads.

14 August 2026 jhave, with Claude Opus 5 github.com/jhave/narracode

00Orientation

What Narracode is, for someone who has not seen it

Narracode is a set of written instructions that a writer hands to an AI, which forces the AI to work the way a writer works: in separate passes, with its memory kept outside itself in files the writer can read and correct.

That sentence is the whole thing, and everything below is a consequence of it. But it is worth slowing down on each part, because each part is a decision that could have gone the other way.

Separate passes

If you ask a language model to write a story, it writes a story. What comes back is competent and slightly dead — fluent, faintly sentimental, faintly explanatory, and recognisably the same story a thousand other models would produce from the same prompt. This is not a flaw in the model. It is what happens when a system trained to produce the most likely next word is asked for a whole work in one motion: it returns the average of everything it has read.

Narracode never asks for a story. It asks for one operation at a time, from an agent that is only allowed to do that operation. A Compositional pass drafts and is forbidden to critique itself. A Reflexive pass critiques and is forbidden to rewrite. A Structural pass updates the story's memory and is forbidden to produce prose. The separation is not tidiness. It is the mechanism: a model's judgement about a sentence is better than its production of one, so the architecture exists to let the judging pass govern the writing pass instead of happening inside it, where it averages out.

Memory kept outside

A folder of plain text files sits beside the drafts. One tracks who has appeared and how their relationships have shifted. One tracks what has definitively happened. One tracks recurring images. One tracks what the story has promised and not yet paid. They are written in ordinary English, they are short, and the writer can open any of them and change a line.

This is the part that makes Narracode neurosymbolic, a word that means only this: a neural component (the language model, which is good at language and bad at remembering) working with a symbolic component (files with structure, which remember perfectly and cannot write). Neither half is new. The claim is that for literature the seam between them belongs in the open, in files a human can edit, rather than buried inside a model.

Where it came from

Narracode began as a question about tooling. Software development was transformed by agentic AI — systems like Claude Code that hold a codebase in structured memory, work in passes, and let a human steer. Literature was not. The question was whether the architecture transfers: not can AI write fiction, which is answered and boring, but can the scaffolding that made AI useful for code be rebuilt for prose. Twenty-six stories and roughly 124,000 words later, it is a working proof of concept.

01The question

An intuition, offered vaguely on purpose

This week began with a hunch, put deliberately loosely:

A physics-based model would be appropriate for capturing the emotional state of characters and reader; a graph or graph neural network would deliver plot structure; the language model would do the actual writing.

Three layers, three technologies, one for each of the things a story is made of. It is an appealing shape. It is also, on inspection, two-thirds right and one-third a category error, and the most useful thing about it turns out to be something it did not intend.

What it got right, and why it matters that it was already true

The three layers already exist in Narracode. Emotional state is character-interiority.md and reader-state.md. Plot structure is graph.md and obligations.md. Prose is the model. They are simply written as sentences rather than as numbers.

So the question was never should we add these layers. It was much narrower, and much cheaper to answer:

Which of these files should stop being prose and start carrying numbers?

That reframing costs nothing. No new model, no training run, no rewrite. It is a decision about four fields in a file that already exists.

What it got wrong

A graph and a graph neural network are unrelated proposals sharing a word. A graph is a data structure — nodes, edges, a thing you can look at. A graph neural network is a learned function that turns graphs into lists of numbers. To build one you need thousands of labelled examples; this project has twenty-six stories. Its output is a vector, not a scene. And the task it would perform — what plausibly happens next? — is the one task a large language model is best at, because that is substantially what predicting the next word in a novel is. Keep the graph. Drop the neural.

The layering implies a pipeline, and the pipeline is the historical failure. Physics decides the emotional target, the graph decides the events, the model renders them into sentences. This is the architecture of essentially every symbolic story generator from 1977 onward, and it fails at the same joint every time: the planner produces a correct sequence of events, and the prose that comes out is dead. In literature the arrow runs both ways. Sentences generate plot. A line of dialogue that surprises you rewrites the character who said it, and that rewriting is frequently the reason to keep going.

So the physics cannot be a controller. It has to be an instrument — something that takes a reading after the draft, and shows it to you.

The rule that followed

Measurement belongs to the outer loop. Any number the harness computes is a reading taken after the fact, never a target set before it. A structural quantity that becomes a goal stops describing the story and starts writing it.

This is now a sentence in the harness itself. It exists because of what Step 06 found.

02Precedent

Checking whether anyone has done this

Before building anything, the intuition was checked against fifty years of people having the same idea. They had. Combining different kinds of AI to make narrative has been the norm rather than the exception, and the useful finding is not whether but which combinations survived.

The symbolic era built planners with English generators bolted on — Talespin, Minstrel, Brutus. Correct plots, dead sentences. The affective-agent tradition (EMA, FAtiMA, the OCC lineage) built genuinely sophisticated models of what a character feels, and produced no narrative tension at all, because character emotion is not narrative tension: a character who feels nothing can devastate a reader, and a weeping character can produce nothing. The systems that did generate felt suspense modelled the reader's beliefs, not anyone's feelings. In the current era, Dramatron, Agents' Room and Generative Agents all keep their structure outside the model in an inspectable store the model reads and writes.

Structure external to the model wins. Structure learned into a second network's weights does not.

A second regularity is the direct answer to the original question. The successful ensembles are heterogeneous in representation — graphs, numbers, text, constraints all in play — and homogeneous in engine: one language model playing several strictly separated roles. Ensembles of different model families are rare in literary generation, and the reason is interface cost. Every seam between families needs a translation layer, and the translation is where the literary information dies.

Narracode is already on the winning side of both regularities. Read strictly, the original intuition proposed moving to the losing side of the second one.

One formal result is worth more than the rest. In 2015 three economists — Ely, Frankel and Kamenica — published definitions of suspense and surprise that are precise enough to compute. Suspense in a moment is the variance of what your beliefs will be in the next moment: how much you might be about to move. Surprise is how far your beliefs just moved. Both are properties of a reader's belief path, not of the text's vocabulary, which means they sidestep the problem that sentiment analysis cannot see irony. Their paper applies the result to, among other things, the design of mystery novels. Hold on to the fact that it is a design result. It returns in Step 07 in a form that is much less comfortable.

03Blocker

Finding the thing that was already built and never used

Before adding anything, the repository was read. This turned up a report dated 24 May 2026 designing an Affect module — a per-character file recording not which emotions a character has but the shape of their emotional process: the specific bodily registers they feel things in, the pairs of feelings they are permitted to hold at once without resolving, their recurring misattachments, and what they cannot yet see about themselves.

Its design principle is precise and worth stating, because it is the best idea in the repository. Cliché enters when a model maps a named emotion onto its default rendering. So the file refuses to name emotions. It supplies primitives that have no default rendering attached — a shape, a valence pair, a bodily register, a latency, a refusal — and forces the model to invent, because its inputs are not pre-mapped to outputs anywhere in its training.

It was implemented in a test version of the harness on 29 May. It was never promoted into the live one. Across twenty-six stories, no affect.md has ever been written.

Eighty-two days. Zero trials.

This is the most important finding of the week and it is not a technical one. Any physics of emotion would have been a numerical refinement of a module nobody had tested once. Refining an untested thing is the most expensive way to learn nothing. So the first action was not to build: it was to promote what already existed and make it usable.

One thing the promotion added

The May design specified which affect primitives exist. It said nothing about how much, and that omission is the module's real failure mode. jhave named it in one line: affect is like an effect in music; finding the correct balance is subtle.

An effect has a level. The entries in an affect file are not a description of how much feeling the prose contains — they are a processing chain, and a chain applied at full strength to every scene produces uniformly saturated prose. Uniform saturation destroys the dynamic range that lets any single moment land. An affect module without a level control makes every scene the loudest scene.

Three rules now govern the module, and they matter more than its schema:

  • Set the level per scene, not per project. Dry, low, present, wet. Most literary scenes are dry or low. A wet scene earns its saturation from the dry ones around it.
  • Judge the mix in the mix. Never evaluate a scene's affect by reading that scene alone. This is enforced mechanically — the critique pass reads a scene together with its two neighbours, or omits the affect section rather than guess.
  • Effects come off first. When a scene is not working, reduce the affect layer before adding to it. The instinct to fix a flat scene with more interiority is exactly the instinct that produces the sentimental default the harness exists to interrupt.
04Instrument

Building the smallest possible measurement

The cheapest place to put a physics is not emotion. It is the thing a story has promised and not yet paid.

Obligation

Something the story has made the reader wait for. A planted object, an unanswered question, a withheld piece of information, an emotional debt. Narracode has always kept a list of these in a file. Chekhov's gun is an obligation; so is a door the narration mentions twice and does not open.

The insight is that an obligation is not binary. A planted detail is vivid in the reader's hands for a scene or two and then fades. A story that finally answers a question the reader has already released feels like an answer to a question nobody asked. So the ledger tracks the fading, with one rule:

The rule, in full

Every scene that touches an obligation resets its salience to 1.0. Every scene that does not multiplies it by 0.5 ^ (1 / half-life). Below 0.1 it is marked faded — not resolved, not forgotten, but no longer something the reader is actively holding.

That is the entire physics. Exponential decay with impulse resets — the mathematics of a struck bell. Each obligation carries four fields: when it was planted, when it was last touched, its half-life in scenes, and its current salience. Summing the live salience gives one number per scene: how much the reader is currently holding.

The part that makes it honest

How do you know whether a scene "touched" an obligation? If the answer is the AI decided it did, the measurement is unfalsifiable — the same system produces the story and grades it.

So each obligation additionally declares its probes: the literal words that count as a touch. The balloon declares balloon. The dragonfly declares dragonfly. The probes live in the file, in the open, and anyone can re-run the count and get the same numbers. Touch detection became reproducible rather than recalled.

This turned out to be the most consequential design decision of the week, for a reason nobody anticipated. See Step 06.

05Protocol

Committing to the answer before looking

The instrument was first run on Interim Edge, a story already in the repository. It produced a legible result. It was also worthless as evidence, and the reason is worth spelling out for a literary audience, because it is the single most common way that quantitative claims about art go wrong.

The probes for that first run were written after reading the story's scene ledger, by the same pass that then ran the analysis. Nothing was falsified. But when you choose your measuring instrument with the answer already in view, you will unconsciously choose one that finds what you expect. The result showed that the tool worked. It showed nothing about whether the measurement means anything.

Pre-registration

Writing down exactly what you will measure, and what you predict, before you look at the data — and then not revising it afterwards. Standard practice in clinical trials, still rare in the humanities. It costs nothing and it is the difference between a finding and an anecdote.

So for the two unpublished stories the protocol was: read only the obligations file. Write the probes and half-lives from that alone. Write down what you predict, and write down which probes you already expect to fail. Commit all of it to version control. Then open the drafts.

Both probe sets are in the repository's history, timestamped before the drafts were opened. Neither was revised afterwards. Where a probe turned out to be badly chosen it is reported as a miss rather than quietly corrected — which is why Step 06 has as much to say about the failures as the successes.

Three finished pieces produce three distinguishable shapes, and the differences correspond to things a reader could name without the arithmetic. That is the result the experiment needed.

Interim Edge accumulates and never lets go

The curve rises monotonically across seven sections and never falls once. Its obligations file says "Resolved: (none — resolution refused as formal principle)" and nine of thirteen entries are annotated (Never answer.) The ledger reproduced that declared poetics from the field arithmetic alone, without being told it. Its final section then re-touches eleven of thirteen threads on the way out — not a passive ending but an active re-arming.

Vetch releases — and this is the finding

It climbs to 8.79 through the seventh movement, then the eighth touches exactly one obligation of eleven and lets the rest decay. It is the only final section of the three that stops holding.

The movement is titled Flatness. The curve goes flat.

An independently chosen title and an independently computed number agreeing about what a section does is the closest thing to validation in the whole run. Nobody told the instrument what the movement was called.

Alpha-Gaia, and three things the count caught

The only curve with a genuine interior decline, dipping through the two most feed-dense sections and recovering at the end. It also produced three findings that were not visible before, each checkable by anyone:

  • An obligation was never planted. The first entry in the file describes a greyed-out field in a form, marked "Planted early, never explained." In the draft, the word greyed appears zero times. So does gray. So does the phrase will not take input. The five hits on field are all ballfield. The obligation carries the only explicit ceiling in any of the three stories — must not be returned to more than twice — and satisfies it by never appearing.
  • A thread required to carry the ending appears once, in the middle. The file flags it as "the most likely to be left as decoration. It has to carry the ending." It appears in section three, and nowhere else — checked under three alternative names in case it was carried differently.
  • The park drops out of exactly the sections its own risk note predicted. The file warns that under the weight of four feed items the bench can vanish. It vanishes from sections four and five, the two densest.

Two of that story's three self-declared risks are confirmed as having actually happened. The file knew what to worry about; it could not see that the worry had come true.

Where the blind probes failed — and the finding underneath

Vetch's probes mostly did not work. Its obligation "the figure must appear without being explained" never fired, because the word figure appears zero times in the drafts; shape appears twelve times. That is a probe miss, not an absence — and it was predicted in the pre-registration, which is the entire reason predictions get written down.

But compare the two files:

The difference is not the stories. It is how each file was written. One names objects. The other names craft requirements. Both are legitimate things to care about, but only the first is something the prose puts on the page in words, and only the first can be counted.

An obligation is what the reader is holding — and a reader holds objects, images and open questions, not notes to the writer.

“Kwesi must be right at least twice” is true, useful, and belongs somewhere else. This is now a rule in the harness. It is a change to how a human writes a file, discovered by a machine failing to read it — which is a fair description of what this whole method is for.

The finding that is only arithmetic

Not one obligation in any of the three stories faded. That is not three stories all refusing to release; it is a calibration error. At a half-life of three scenes, an untouched obligation needs ten consecutive untouched scenes to cross the floor. These pieces are seven and eight sections long. The floor was unreachable by construction. Half-lives were set for novels and applied to short fiction, and should be one or two.

The instrument's most discriminative output turned out not to be the fade count at all, but the number added almost incidentally: what the final section chooses to touch. Eleven of thirteen against one of eleven. That single figure separates the three pieces more cleanly than anything else measured.

07The wormhole

The same curve, drawn for the opposite reason

The most sophisticated practitioners of short-form narrative alive today are not novelists. They are the people building vertical micro-drama and the advertisers who fund them, and they have operationalised engagement to a precision no literary institution has attempted.

The numbers are not small. Vertical drama apps run episodes of sixty to ninety seconds, each ending on a cliffhanger, with the next episode beginning before the brain registers that the last one ended. Reported figures put US users at over half an hour a day inside a single such app — ahead of Netflix on mobile — and typical sessions at twenty or more consecutive one-minute episodes. Production teams report tuning the freeze-frame to the second: retention measurably spikes when the cut lands between seconds fifty-five and fifty-eight of a sixty-second episode. Writers there do not write to the page. They write to the second, and they A/B test cliffhanger configurations against retention at a sample size no humanities department will ever have.

So: should Narracode go there for its next instrument? The honest answer has two halves, and they point in opposite directions.

Yes — because they found the same variable first

The psychological mechanism underneath the cliffhanger is the Zeigarnik effect: unfinished things occupy memory more than finished ones. Unresolved questions and incomplete narratives create a cognitive tension that persists until closure.

That is the obligation ledger. Precisely, not analogously. An open loop is an unpaid obligation, and what a retention engine maximises is the count of open loops per unit time with none permitted to fade. The advertising industry arrived at the salience variable decades before this project did, gave it a different name, and built an economy on it.

Which means: the metric cannot tell literature from engagement optimisation. They produce the same curve.

Look again at Interim Edge — monotone rising, zero fade events, a final section that re-arms almost every thread. That is, structurally, an optimised retention curve. It was produced by a poetics of principled refusal, by a writer who is refusing resolution as an aesthetic commitment. And it is the same shape a system would produce if it were trying to keep you scrolling.

This is an uncomfortable result and it is the most valuable thing in this document. The instrument measures how much the reader is holding. It is blind to why, and blind to what kind.

No — because their objective function is the thing literature refuses

Three differences separate the two practices, and none of them is visible in the curve:

  • Closability. A retention loop is always closable and is always eventually closed — the payoff is what trains the return. Interim Edge's obligations are annotated (Never answer.) as a formal principle. Same shape, opposite contract with the reader.
  • What the loops are about. Engagement loops are plot-instrumental: will she discover he is the billionaire. Literary loops in these stories are perceptual and unanswerable: whether the white-haired woman is one person, a face-model, or a recurrence. One is a question with an answer being withheld. The other is a question the world does not contain an answer to.
  • What the holding is for. Narrative transportation research finds that transported readers remember content better, align their beliefs with the narrative, and engage less critically. Reduced critical engagement is the goal of persuasive narrative. It is arguably the opposite of what literature is for.

And here is the sharpest version, which the data already contains. Vetch's eighth movement — the one that touches a single obligation and lets everything else go — is a move that no engagement-optimised format can ever make. A retention system cannot write Flatness. Releasing the reader is precisely the behaviour it exists to prevent.

Release is the literary signature. And it is measurable.

What the next instrument should therefore be

Not a retention curve. A second axis, crossed against salience: for each obligation, is it closable or unclosable, instrumental or perceptual? Salience tells you how much the reader is holding; that axis tells you what kind of thing it is. Together they separate the two practices that the single number confuses — and the separation is the actual research question, considerably more interesting than either measure alone.

The asymmetry to keep in view

Recall that the suspense-and-surprise result is a design theorem: it solves for the optimal way to release information to a Bayesian audience. The same mathematics serves the novelist and the retention engineer, and it does not care which one is holding it.

Engagement optimisation has enormous economic gravity behind it. Literary refusal has none. So if this harness is ever permitted to optimise its own numbers, it will drift toward the vertical-drama attractor by default — not by anyone's decision, but because that is the direction the slope runs. Which is why the number stays read-only, and why the rule in Step 01 is written into the harness rather than merely believed.

08Standing

What is and is not established

Established. A minimal decay model over a hand-maintained list produces distinguishable shapes for three finished pieces, along axes that correspond to describable narrative behaviour. In one case the number agrees with a section title chosen independently of it. The method surfaced three concrete facts about a finished story that its author's own notes had not caught, two of which that story's own risk register had predicted. And the exercise produced two changes to the harness — write obligations as objects; scale half-lives to the length of the piece — that were discovered by measurement failing, not by measurement succeeding.

Not established. Whether any of this tracks quality. The falsification condition was set in advance: if the curves do not separate the pieces the writer rates highly from the ones he does not, the approach has no purchase and stops. Three stories is a small sample and his ranking has not been collected. Every number here is provisional.

Worth noting against the danger. Every finding this week is negative — a thread that vanished, an obligation never planted, a park that dropped out of two sections. Not one of them suggests a quantity to increase. So far the ledger has been useful exactly as intended, and useless as a controller. That is the result to hope for and it should be checked again each time.

The argument this is evidence for

Narracode's claim was never that AI can write literature. It is that the architecture of a narrative generator is not neutral — that the structural logic of a system encodes a set of presuppositions about what a story is, and therefore constitutes a narrative philosophy expressed as code.

This week is an instance of that claim being tested rather than asserted. A loose intuition about physics and graphs was checked against fifty years of prior art, reduced to the smallest falsifiable component, pre-registered, run blind, and permitted to fail in public. It changed the harness twice — and both changes were to how a human writes a file. The next question it opened comes from advertising research rather than literary theory, and answering it honestly required admitting that the instrument cannot yet tell the two apart.

That is the ongoing conversation the architecture is supposed to be. Not a system that writes, but a system that keeps producing the next question in a form specific enough to be wrong about.

—Glossary

Terms, defined once

Harness

The written instructions and file structure that constrain how the AI works. Narracode is the harness; the language model is a component it drives.

Pass / agent

One operation the model is allowed to perform in one invocation — draft, critique, update memory — with the others forbidden.

Obligation

Something the story has made the reader wait for.

Salience

A number from 0 to 1 estimating how actively a reader is still holding a given obligation.

Half-life

How many scenes it takes, without a mention, for the reader's hold on something to halve.

Probe

The literal words that count as the story touching an obligation, declared in the file so the count is reproducible.

Neurosymbolic

A system combining a neural component (the language model) with a symbolic one (structured files). In Narracode the seam between them is deliberately in the open, where a human can edit it.
