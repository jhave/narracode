# Pragmatic Narracode Revision Plan

Focus: layered structural memory, scene cycle, and check protocols without command-template complexity

## Purpose

This plan narrows the earlier `2026-05-14_0845_CEST_gpt5.5-codex_narracode-literary-capacity-plan.md`.

The goal is to improve Narracode's capacity for full literary storytelling without turning it into a technical CLI or command system. Humanities authors should still be able to use ordinary language:

- "Keep going."
- "Write the next scene."
- "This feels thin."
- "Check whether this is drifting."
- "Save this."
- "Let's revise the last scene."

The harness should infer the relevant agents, checks, and loops. The complexity should live inside Narracode, not in the user's command vocabulary.

## What We Are Keeping

From the earlier plan, keep:

- Layered structural memory.
- Scene-cycle thinking.
- Check protocols.
- Natural-language invocation.
- Human edit learning.
- The principle that Narracode should preserve accumulated literary pressure over time.

## What We Are Not Implementing Now

Do not implement command templates yet.

The earlier plan proposed commands such as `/scene`, `/context-pack`, `/reader-sim`, and `/revise-lines`. These may be useful later for technical users, but they risk making Narracode feel procedural in the wrong way.

For now, the harness should keep using intent recognition. Internally, it may behave as if there are commands, but the author should not need to see or invoke them.

Also defer:

- Full CLI design.
- Complex reader simulation.
- Multiple specialized revision agents.
- Formal score-based evaluation.
- Any extensive automation that makes the writing process feel clerical.

## Core Implementation Idea

Narracode should expand from three structural files into a small set of literary memory files.

The existing files are good but too thin:

```text
structural/
  graph.md
  time-constants.md
  history.md
```

They mostly protect factual continuity. Full literary storytelling needs memory for softer but equally important pressures:

- what the story has promised
- what images are recurring
- what the reader is expected to remember
- what each scene does
- what private tensions characters carry
- what tone, rhythm, and atmosphere are accumulating

The pragmatic next step is to add only the structural files that are likely to matter immediately.

## Proposed Structural Files

### 1. `structural/obligations.md`

Tracks promises the story has made.

This file answers:

- What has been planted but not resolved?
- What does the reader expect to return?
- What questions are active?
- What has been withheld?
- What emotional, symbolic, or plot debts exist?

Example entries:

```md
## Active Obligations

- Trygve has not yet understood whether the device body has limits, hunger, sleep, pain, or death.
- Anouk's quiet kindness has been registered but not yet given consequence.
- The airport setting has established transit as both literal travel and moral suspension.

## Resolved Obligations

- Trygve's first transformation shock has moved from panic into reluctant observation.

## Dangerous Neglect

- If the story continues much longer without returning to Trygve's lost social power, the class dimension may fade.
```

Why it matters:

Stories fail when they forget what they have taught the reader to wait for. This file keeps waiting alive.

### 2. `structural/motifs.md`

Tracks recurring images, objects, gestures, phrases, atmospheres, and symbolic materials.

This file answers:

- What images are accumulating?
- Which objects or gestures are becoming charged?
- Which motifs should return altered, not merely repeated?
- Which motifs are becoming too obvious?

Example entries:

```md
## Active Motifs

- Pockets: concealment, warmth, involuntary intimacy, class reversal.
- Airports: transit, anonymity, systems too large for private grievance.
- Small screens: reduced agency, forced visibility, toy-like humiliation.
- Hearts heard through fabric: other people's life continuing without permission.

## Motifs To Avoid Overusing

- Direct statements about transformation as moral lesson.
- Too many explicit references to scale unless physically grounded.
```

Why it matters:

Motif is one of the ways literary memory survives across scenes. The model needs a place to notice it.

### 3. `structural/scene-ledger.md`

Tracks each scene as a functional unit.

This file answers:

- What happened in each scene?
- Whose perception governed it?
- What changed?
- What did the scene add to pressure, relation, motif, or plot?
- What should the next scene not repeat?

Example entries:

```md
| Scene | File | Location/Time | Function | Turn | Aftermath |
|---|---|---|---|---|---|
| 0 | drafts/0-bergen-departure.md | Bergen airport, morning | Transformation and first humiliation | Trygve becomes dependent on strangers | Establishes scale, class reversal, object-body |
| 1 | drafts/1-the-magnet.md | Flight / pocket | Intimacy without consent or control | Trygve hears another person's heart | Softens panic into observation |
```

Why it matters:

This prevents scenes from becoming merely sequential. Each scene should do something.

### 4. `structural/character-interiority.md`

Tracks private states that may not yet be visible in action.

This file answers:

- What does each major character want?
- What are they avoiding?
- What do they know privately?
- What contradictions do they carry?
- What has changed inside them even if nothing external has changed?
- What arc potentials are forming?
- What cathartic inflection points might become possible later?

Example entries:

```md
## Trygve Aas

- Public identity: rich, bitter, accustomed to command.
- Current private state: frightened by dependence but beginning to receive accidental care.
- Avoidance: does not want to interpret kindness as anything other than weakness or mistake.
- Contradiction: wants to be seen, but the only available form of being seen is humiliating.
- Arc potential: movement from command to receptivity, but only if mediated by concrete dependence rather than moral lecture.
- Possible cathartic inflection: a moment where Trygve chooses not to exploit a small available power.

## Anouk

- Public identity: airline worker performing routine care.
- Current private state: tired, practical, not sentimental.
- Narrative function: ordinary competence becomes a force that changes Trygve without intending to.
```

Why it matters:

LLMs often flatten characters into visible actions. This file keeps invisible pressure available.

### 5. `structural/reader-state.md`

This is a light version of the earlier "Reader Simulation Agent." It should not become a complicated fake-reader exercise.

This file answers:

- What does a reader likely understand right now?
- What is the reader waiting for?
- What might be confusing in a good way?
- What might be confusing in an accidental way?
- What emotional charge has accumulated?
- What plausible plot paths could answer reader expectations?
- What plausible plot paths could defy those expectations while remaining credible inside the story-world?

Example entries:

```md
## Current Reader Understanding

- Trygve has been transformed into a small device and is now dependent on strangers.
- The story is not behaving like a quest; it is behaving like a sequence of humiliating, intimate transfers.
- Care is emerging through logistics rather than declared compassion.

## Reader Expectations

- The reader expects the transformation to reveal Trygve's former cruelty indirectly.
- The reader expects travel locations to matter as systems, not postcards.

## Plausible Defiance Paths

- The story could refuse a conventional return-to-human resolution if Trygve's changed scale becomes the real ending.
- The story could let a minor handler become structurally important, defying the expectation that only Trygve's former social world matters.

## Productive Mystery

- The metaphysics of the transformation remain unexplained. This is currently acceptable.

## Accidental Confusion Risk

- If too many handlers appear without scene anchoring, the reader may lose emotional continuity.
```

Why it matters:

This is not a market-research reader. It is a continuity file for attention.

When the author asks "what could happen next?" or "what plot turns are available?", Narracode should draw on `reader-state.md`, `character-interiority.md`, `obligations.md`, `scene-ledger.md`, and `motifs.md` to suggest possibilities. It should not surface these possibilities every time it drafts.

## Files To Defer

The earlier plan suggested more files. Do not add all of them yet.

Defer:

- `affect.md`: useful, but may overlap with `reader-state.md` and `character-interiority.md`.
- `line-pressure-check.md` as a separate file: start with simpler check notes.
- `accepted-style-rules.md`: keep human edit learning in the existing `edit-observations.md` / `POETICS.md` process for now.
- `context/next-scene-pack.md`: implement the idea implicitly first, then decide whether the file is useful.

## What Is A Next Scene Pack?

A next scene pack is not a new kind of draft. It is a small temporary briefing the model assembles before writing.

It answers:

- Where are we in the story?
- What matters right now?
- What must not be forgotten?
- What should the next scene probably do?
- What constraints from `POETICS.md` are active?
- What motifs, obligations, and private states should remain alive?

The reason it may be useful:

When a model reads too much, it often summarizes everything into mush. A scene pack gives it a small, sharp field of attention.

However, it may feel like bureaucracy if written as a visible file every time.

Pragmatic recommendation:

Do not create `context/next-scene-pack.md` yet.

Instead, update `narracode.md` so the Compositional Agent performs an internal pre-scene briefing by reading:

- `POETICS.md`
- `structural/history.md`
- `structural/time-constants.md`
- `structural/graph.md`
- `structural/obligations.md`
- `structural/motifs.md`
- `structural/scene-ledger.md`
- `structural/character-interiority.md`
- `structural/reader-state.md`
- the latest draft
- the user's current request

Then it drafts. If this hidden briefing proves useful, later versions can externalize it as `context/next-scene-pack.md`.

## Scene Cycle

The scene cycle is the main workflow improvement.

When the user says something like "keep going" or "write the next scene," the harness should automatically do this:

1. **Orient locally**
   - Read `POETICS.md`.
   - Read the latest draft.
   - Read all structural files.

2. **Update structural state**
   - Refresh history, graph, time, obligations, motifs, scene ledger, character interiority, and reader state.
   - Keep this concise.

3. **Infer the next scene's task**
   - What is the next scene likely responsible for?
   - Which obligation, motif, relation, or pressure should it carry?
   - What should it avoid repeating?

4. **Draft the scene**
   - Write a new file in `drafts/`.
   - Do not overwrite.
   - Do not self-critique inside the draft.

5. **Run check protocols**
   - After drafting, check the new scene against the project.
   - Record findings briefly, either in `critiques/` or as a short post-draft note, depending on how strict the harness should be.

6. **Stop**
   - Do not automatically revise unless the user asks.
   - Do not continue into another scene.

The important shift:

The model is no longer merely continuing. It is continuing after refreshing the story's accumulated pressures.

## Check Protocols

Check protocols should be simple, literary, and non-numeric.

They should identify risks and opportunities, not grade the work.

### 1. Continuity Check

Questions:

- Did the new scene contradict established facts?
- Did it break timeline, location, relation, or causality?
- Did it forget a physical constraint?

Output:

```md
## Continuity Check

- No hard contradiction found.
- Possible issue: the scene implies Anouk still has the keychain after it was passed to Karim. Clarify transfer point.
```

### 2. Obligation Check

Questions:

- Did the scene honor active promises?
- Did it accidentally ignore something urgent?
- Did it create new obligations?
- Did it resolve anything too easily?

Output:

```md
## Obligation Check

- New obligation: Trygve hears the handler mention a daughter; if this detail remains, it should matter later or be cut.
- Existing obligation maintained: Trygve's social power remains inaccessible but psychologically active.
```

### 3. Motif Check

Questions:

- Which motifs returned?
- Did they return transformed or merely repeated?
- Is any image becoming too obvious?

Output:

```md
## Motif Check

- Pocket motif returns with a different texture: less concealment, more warmth.
- Avoid more explicit scale metaphors in the next scene; the object-body already carries this.
```

### 4. Scene Function Check

Questions:

- What did the scene do?
- Did anything change?
- Was the change plot, perception, relation, pressure, rhythm, or atmosphere?
- Could the scene be cut without loss?

Output:

```md
## Scene Function Check

- Function: shifts Trygve from panic into unwilling attention.
- Turn: he notices another person's fatigue without converting it into contempt.
- Risk: the final paragraph explains the change too directly.
```

### 5. Voice / Default Check

Questions:

- Did the prose become generic?
- Did it over-explain emotion?
- Did it become too smooth, sentimental, or summary-like?
- Did it preserve the project's attentional dialect?

Output:

```md
## Voice Check

- Strongest passages are object-specific and bodily.
- Weakest passages explain moral change in abstract terms.
- Recommendation: replace direct insight with one more observed detail.
```

### 6. Reader-State Check

Questions:

- What does the reader now expect?
- What emotional pressure has accumulated?
- What might be unclear accidentally?
- What mystery remains productive?

Output:

```md
## Reader-State Check

- Reader now expects each handler to reveal a different social scale.
- Productive mystery remains: why the transformation occurred.
- Risk: too many locations may turn the structure into itinerary rather than transformation.
```

## Where Check Results Should Go

Start simple.

Option A:

- Write checks into `critiques/check-[draft-name].md`.

Option B:

- Append a compact "Post-scene check" section to `structural/scene-ledger.md`.

Recommended first implementation:

Use `critiques/check-[draft-name].md`.

Reason:

- Keeps structural files clean.
- Lets the author inspect the check separately.
- Preserves the principle that critique does not rewrite the draft.
- Keeps checks succinct: one file per draft, with short sections and bullets.

## Practical Success Criteria

This revision is working if:

- The author can still use ordinary language.
- The new structural files help the model remember literary pressure, not just plot.
- Drafts become less generic because active motifs, obligations, and reader expectations are present.
- Checks reveal useful next decisions without forcing revisions.
- The process does not feel like filling forms.

This revision is failing if:

- The author has to learn commands.
- The model spends more time maintaining files than writing.
- Structural files become bloated summaries.
- Checks become moralistic or genre-policing.
- The prose becomes over-planned and loses surprise.

## First Implementation Recommendation

Begin by editing `narracode.md`, not by building tools.

Make the harness more capable in markdown first:

1. Add the five new structural files to project initialization.
2. Define what each file does.
3. Expand the Structural Agent.
4. Add Check Mode to the Reflexive Agent.
5. Add `post_draft_check` as an automatic hook.

Then test on one story.

Only after this feels useful should Narracode consider scripts, command templates, or a CLI.

## Guiding Revision

Narracode should not ask humanities authors to become operators.

It should let them speak naturally, while the harness quietly maintains the deeper literary memory needed for long-form storytelling.
