# Substep 1.4 — Alignment and operation typing

**Model: Sonnet 4.6.** The spec below is exact; errors here are loud rather than silent.

**Output:** `tools/align.py`

Requires 1.2 (ledger) and 1.3 (segmenter) complete.

---

## Objective

Given two versions of the same draft — machine before, human after — produce the list of aligned span pairs and label each with the operation the edit performed.

---

## Inputs

- `corpus/provenance.yaml` — determines which snapshot pairs are eligible
- `tools/segment.py` — the fixed segmenter
- draft `.md` files from `versions/<snapshot>/drafts/`

---

## Method

1. **Select eligible transitions.** Consecutive snapshots within one story where earlier is `machine`, later is `human`, both `usable: true`. Apply the `boundary` field. Nothing else is eligible.

2. **Match drafts across the two snapshots — filename first, then content.**

   a. Exact filename match.

   b. For drafts left unmatched on **both** sides, compute `SequenceMatcher.quick_ratio()` over the first 20,000 characters of each candidate pair. Take matches greedily, highest first, accepting only ratio ≥ 0.50, each file used once. Record `match: content` and the ratio on every pair produced this way.

   c. Anything still unmatched goes in the exceptions list.

   **This rule replaces an earlier instruction to skip unmatched filenames entirely, which was wrong.** In `01-07-2026_Cussinct` the drafts run `v1 1-cussinct.md` → `v2 1-cussinct.md` → `v3 1-cussinct-human-edit-snapshot.md` → `v4 1-cussinct.md`. Exact-name matching drops the `v2 → v3` transition, which is the machine-to-human pair — the single most valuable pair in that story. Seven further pairs across the corpus are recovered the same way.

   Note the distinction: matching on **content similarity** is measurable and verifiable. Matching on **filename similarity** is guesswork. Do the first, never the second.

3. **Segment both** with `tools/segment.py`.

4. **Align** with `difflib.SequenceMatcher` over the sentence lists. Use `autojunk=False` — the default junk heuristic misbehaves on repetitive literary text.

5. **Sub-align inside every non-`equal` block. Do not emit a block as one pair.**

   A `replace` block covering several sentences on both sides is *several* edits, not one. Emitting it whole destroys the corpus. Measured on the canonical `Interim Edge` `v2 → v3` pair: block-level emission yields **2 pairs**; sub-alignment yields **33**, and the benchmark doc documents 13 hand-counted operations in that passage. Block emission was hiding an order of magnitude of signal.

   Sub-alignment must be **order-preserving**. Within a block, score every candidate sentence pair by `SequenceMatcher.ratio()`, sort descending, and accept a pair only if it neither reuses an index nor *crosses* an already-accepted pair — that is, reject `(i, j)` if some accepted `(pi, pj)` has `(i - pi) * (j - pj) < 0`. Threshold 0.40.

   Greedy similarity **without** the crossing constraint is worse than emitting blocks, because it manufactures pairs. Measured on the same passage, it produced `'Counter.'` → `'Coffee.'` and `'Bag saying COFFEE…'` → `'Heart skewed sideways, love, a medical condition.'` — unrelated sentences matched on surface similarity. With the constraint the same passage yields `'Counter.'` → `'Counter where hips meet.'` and `'Chicory and a legume.'` → `'Chicory.'`, which are the documented registry edits.

   Sentences left unmatched inside a block become `delete` (before side) or `insert` (after side).

6. **Map each sub-aligned pair to an operation:**

   | shape | operation |
   |---|---|
   | before only | `delete` |
   | after only | `insert` |
   | 1 → 1, length decreased ≥15% | `shorten` |
   | 1 → 1, length increased ≥15% | `lengthen` |
   | 1 → 1, otherwise | `substitute` |
   | 1 → n within the block | `split` |
   | n → 1 within the block | `join` |

7. **Discard no-signal pairs.** Drop any pair whose before and after are identical after whitespace normalisation. Measured: 24 of 776 spans (3.1%) across the corpus. These are segmentation artefacts and carry no displacement.

8. **For `draft → published` pairs, emit substitutions only.** Published `index.html` is compared against the last snapshotted draft, and that draft is often a fragment — in `15-05-2026_The_Author_Was_Already_Dead` the draft is 819 words against a 3,894-word published story. Inserts there represent composition that was never snapshotted, not editing, and counting them inflated that story from 1 real pair to 296. Substitutions align an existing sentence to its edited form and are the only trustworthy signal in these pairs.

9. **Compute an alignment confidence** for every emitted pair: token-level `SequenceMatcher.ratio()` between the before text and after text.

10. **Apply the confidence gate.** Emit pairs with ratio ≥ 0.30. Below that, the "pair" is two unrelated passages that happened to land in the same opcode block. Record them in the exceptions list with their ratio; do not emit them.

11. **Detect reorder.** If a `delete` block's text reappears as an `insert` block elsewhere in the same draft with ratio ≥ 0.85, collapse both into a single `reorder` pair. Run this pass after sub-alignment.

---

## Do not

- Call a model to align sentences. If `SequenceMatcher` cannot align a passage, drop it and log it. A dropped pair costs one sample; a hallucinated alignment corrupts the mean.
- Match drafts on filename *similarity*. Content similarity only (Method 2b).
- Emit pairs from `equal` opcodes.
- Silently drop anything. Everything not emitted goes in the exceptions list with a reason.
- Tune the 0.30 gate to increase yield. If yield is low, report it — that is a finding about the corpus, not a parameter to adjust.

---

## Output

One record per pair, passed to 1.5 for serialisation:

```python
{
  "story": "30-07-2026_Interim_Edge",
  "from_snapshot": "v2-2026-07-30-tell-scan",
  "to_snapshot": "v3-2026-07-30-jhave-section1",
  "draft": "7-condensed-final.md",
  "index": 14,                    # sentence index in the before text
  "before": "Two minutes forty, and he stood there for all of it.",
  "after": "Two minutes forty.",
  "op": "shorten",
  "confidence": 0.61
}
```

Plus `corpus/alignment_exceptions.md`: every skipped block, with story, draft, reason, and ratio where applicable.

---

## Failure modes specific to this substep

- **`autojunk` silently discarding content.** `SequenceMatcher` treats elements appearing in >1% of a long sequence as junk. In prose with repeated short fragments this drops real sentences. Set `autojunk=False` and verify the sentence count in equals count out.
- **Whole-file replacement.** If a human rewrote a draft wholesale, the aligner produces one enormous `rewrite` pair with low confidence. This is correct behaviour and the gate will drop it. Log it — a story appearing only as dropped wholesale rewrites is worth knowing about.
- **Off-by-one on indices.** The `index` field must refer to the before text. Assert it.
- **Counting a `reorder` twice.** After collapsing in step 8, ensure the original `delete` and `insert` are removed.

---

## Acceptance criteria

- [ ] For every eligible transition, sentences-in equals sentences-accounted-for (emitted + equal + excepted)
- [ ] No pair emitted with confidence < 0.30
- [ ] `alignment_exceptions.md` accounts for every non-emitted, non-equal block
- [ ] Operation distribution reported: counts per `op` type across the corpus
- [ ] `autojunk=False` verified in the code
- [ ] Content-matched pairs carry `match: content` and their ratio
- [ ] The Cussinct `v2 -> v3` renamed pair is present in the output
- [ ] Sub-alignment is order-preserving; no accepted pair crosses another
- [ ] Interim Edge `v2 -> v3` yields ~33 pairs, not 2
- [ ] No pair has before == after after whitespace normalisation
- [ ] draft->published pairs contain substitutions only
- [ ] Running twice on the same input produces byte-identical output

## Report honestly

Report the operation distribution. If it is dominated by `rewrite` and `insert` rather than `shorten`, `split` and `delete`, say so — it would mean the corpus records wholesale rewriting rather than line editing, which changes what Step 2 can measure and is worth surfacing before Step 2 runs.
