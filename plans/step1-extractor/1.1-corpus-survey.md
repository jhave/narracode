# Substep 1.1 — Corpus survey

**Model: Opus 4.6.** Judgment on messy data; the failure mode is a clean answer that is wrong.

**Output:** `corpus/survey.md` and `corpus/survey.json`

**Nothing else in Step 1 may begin until this is complete.**

---

## Objective

Produce a complete, verified inventory of what is actually in `Stories written with Narracode/*/versions/`. Not what the naming convention implies — what is there.

## Why this exists

The 08-05 plan claimed provenance was machine-readable from directory names. That claim came from inspecting one story. It does not hold across the corpus. This survey exists because that error was made once already, and everything downstream depends on the answer being right.

---

## Inputs

```
Stories written with Narracode/*/versions/
Stories written with Narracode/*/drafts/
Stories written with Narracode/*/POETICS.md
```

## Do not assume

- That every entry in `versions/` is a directory. Three are loose `.md` backup files.
- That every version directory contains `drafts/`. Bare `v0`, `v1` in `Project_A-0` contain only `edit-observations.md` and `loop-notes.md`.
- That directory names follow one convention. At least four distinct patterns exist.
- That version ordering is lexicographic. `v10` sorts before `v2` as a string.
- That draft filenames are stable between snapshots. A draft may be renamed.
- That all text is UTF-8 clean, or that all files end in a newline.
- That `versions/` is the only place snapshots live.

---

## Method

1. **Enumerate.** For every story directory, list every entry in `versions/`. Record type (directory / file / symlink / other).

2. **Classify each entry** into exactly one of:
   - `snapshot` — a directory containing a `drafts/` subdirectory with at least one `.md` file
   - `metadata-only` — a directory with no `drafts/`
   - `loose-file` — not a directory
   - `other` — anything else; describe it

3. **For each `snapshot`, record:**
   - path
   - parsed version number (as an integer, handling `v10` correctly)
   - date in the name, if any
   - the descriptive tail of the name
   - list of draft filenames, with word count for each
   - whether `POETICS.md` is present in the snapshot

4. **Classify the name's provenance signal** into exactly one of:
   - `explicit-human` — contains `human`, `jhave`, `user`, or `hand`
   - `explicit-machine` — contains `automode`, `auto-run`, `initiator`, `draft`, `tell-scan`, `initial`
   - `ambiguous-temporal` — contains `pre-`, `before-`, `post-`, `after-` (the marker describes an adjacent state, not this one)
   - `content-only` — descriptive of content with no provenance term
   - `none`

   **This is a classification of the name, not a determination of provenance.** Determining actual provenance is substep 1.2. Do not conflate them.

5. **Build the draft-continuity map.** For each story, for each consecutive snapshot pair, list which draft filenames appear in both. This is what 1.4 will diff. Record filenames that appear in one but not the other.

6. **Record every exception.** Unreadable files, encoding errors, empty drafts, snapshots with no drafts, duplicate version numbers.

---

## Output format

`corpus/survey.json` — machine-readable, one record per entry, fields exactly as in Method 3 and 4.

`corpus/survey.md` — human-readable, containing:

- A table: story | snapshots | metadata-only | loose files | drafts total | words total
- A table of every snapshot with its provenance-signal classification
- **A section titled "Ambiguous — needs jhave"** listing every snapshot classified `ambiguous-temporal`, `content-only` or `none`, one per line, with the story, the version, the date, and the draft filenames. This section is the direct input to substep 1.2.
- A section titled "Exceptions" listing everything from Method 6
- A section titled "Assumptions made" stating each assumption explicitly

---

## Failure modes specific to this substep

- **Reporting a total without the exceptions.** "25 stories, 60 snapshots" is not useful if 12 snapshots have no drafts. Always report the usable subset separately from the raw count.
- **Sorting versions as strings.** `v10` must sort after `v9`.
- **Treating `pre-X` as machine and `post-X` as human.** These describe the *content transition*, not who made it. `v0-2026-05-08-pre-geography-shift` is the snapshot before a geography shift; it says nothing about who performed the shift. Classify as `ambiguous-temporal` and move on.
- **Guessing at provenance to make the table look complete.** An honest `content-only` row is correct output. An invented `explicit-machine` row is corruption.

---

## Acceptance criteria

- [ ] Every entry under every `versions/` directory appears in `survey.json` exactly once
- [ ] Counts in `survey.md` are reproducible by re-running the survey script
- [ ] The "Ambiguous — needs jhave" section is present and non-empty (it will not be empty; roughly half the corpus lands there)
- [ ] The "Exceptions" section accounts for every entry not classified as `snapshot`
- [ ] The "Assumptions made" section is present
- [ ] No provenance determination has been made for any `content-only` or `ambiguous-temporal` entry

## Report honestly

State the number of snapshots that are usable for pair extraction and the number that are not, separately. If that usable number is smaller than the plan assumed, say so directly — it changes the sample size available to Step 2 and jhave needs to know before proceeding.
