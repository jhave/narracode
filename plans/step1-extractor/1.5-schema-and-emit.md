# Substep 1.5 — Schema and emit

**Model: Sonnet 4.6.** Mechanical.

**Output:** `tools/extract_pairs.py` (the entry point), `corpus/edit_pairs.jsonl`

Requires 1.4 complete.

---

## Objective

Serialise the aligned pairs to a stable, append-only, human-readable corpus file, and provide the single command that rebuilds it from scratch.

---

## Schema

One JSON object per line. Field order fixed for diff readability.

```json
{"id": "30-07-2026_Interim_Edge/7-condensed-final/0014",
 "story": "30-07-2026_Interim_Edge",
 "draft": "7-condensed-final.md",
 "from_snapshot": "v2-2026-07-30-tell-scan",
 "to_snapshot": "v3-2026-07-30-jhave-section1",
 "date": "2026-07-30",
 "index": 14,
 "before": "Two minutes forty, and he stood there for all of it.",
 "after": "Two minutes forty.",
 "op": "shorten",
 "confidence": 0.61,
 "provenance_source": "name-marker",
 "poetics_ref": "Stories written with Narracode/30-07-2026_Interim_Edge/POETICS.md",
 "extractor_version": "1.0.0",
 "segmenter_version": "1.0.0"}
```

**Field notes:**

- `id` — deterministic: `story/draft-stem/zero-padded-index`. Same input must always produce the same id, so re-running is idempotent.
- `date` — from the *to* snapshot, the date the edit was made.
- `provenance_source` — carried through from `provenance.yaml`. Lets Step 2 weight or exclude jhave-confirmed vs name-marker labels if the two behave differently.
- `poetics_ref` — path, not content. Keeps the pair attached to the project commitments it was made under, which is what keeps the corpus multifaceted rather than averaged.
- `extractor_version`, `segmenter_version` — required. When the segmenter changes, every vector must be recomputed, and these fields are how that is detected.

**No cadence vectors in this file.** Vectors belong to Step 2 and go in a separate file keyed by `id`. Keeping them separate means a change to the vector definition does not require re-extracting the corpus.

---

## Method

1. Write `tools/extract_pairs.py` as the entry point calling 1.3 and 1.4.
2. Read `corpus/provenance.yaml`. Refuse to run if it contains any `provenance: unknown` with `usable: true`.
3. Emit pairs sorted by story, then draft, then index. Stable ordering makes the file diffable.
4. Write `corpus/edit_pairs.jsonl` atomically — to a temp file, then rename.
5. Write `corpus/extract_report.md` alongside it.

---

## CLI

```
python tools/extract_pairs.py --rebuild          # full rebuild from scratch
python tools/extract_pairs.py --story <name>     # single story, prints, does not write
python tools/extract_pairs.py --validate         # re-run, compare to existing, report drift
```

`--rebuild` must be safe to run at any time and must produce byte-identical output given identical inputs.

---

## `corpus/extract_report.md` must contain

- total pairs emitted
- pairs per story
- operation distribution (counts per `op`)
- confidence distribution (min, median, max, count below 0.5)
- eligible transitions found vs transitions yielding at least one pair
- count of exceptions, with a pointer to `alignment_exceptions.md`
- extractor and segmenter versions
- run timestamp and total wall time

---

## Do not

- Store cadence vectors in this file.
- Store the model's interpretation of an edit. Spans and operation type only. The existing 40 `edit-observations.md` files are the format being replaced, not extended.
- Compress or minify. The file must stay greppable and diffable.
- Write incrementally to the real path. Temp file then rename, so an interrupted run cannot leave a half-written corpus.
- Emit records with empty `before` and empty `after` simultaneously.

---

## Acceptance criteria

- [ ] `--rebuild` twice produces byte-identical `edit_pairs.jsonl`
- [ ] Every line is valid JSON with all required fields present
- [ ] `id` values are unique across the file
- [ ] Pair count matches the count reported by 1.4
- [ ] Script exits non-zero with a clear message if `provenance.yaml` has usable unknowns
- [ ] `extract_report.md` is written on every run
- [ ] File is committed to git (it is small, textual, and its history is valuable)

## Report honestly

Report the total pair count plainly. If it is materially below the low hundreds, state that Step 2's test will be underpowered and that jhave should decide whether to proceed, expand the corpus, or stop.
