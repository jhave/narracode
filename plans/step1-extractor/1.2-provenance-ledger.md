# Substep 1.2 — Provenance ledger

**Model: Opus 4.6, with jhave in the loop.** This substep cannot be completed autonomously and must not be.

**Output:** `corpus/provenance.yaml`

---

## Objective

For every snapshot in the corpus, record who produced it — machine or human — as an explicit, human-confirmed fact. The extractor reads only this file. It never infers provenance from a directory name at runtime.

---

## Why this exists

A pair is a displacement: machine output → human edit. If a machine-to-machine transition is labelled as a human edit, its displacement vector enters the corpus pointing in an arbitrary direction. Step 2 averages those vectors. Enough mislabelled pairs and the average points nowhere, Step 2's falsification test returns a false negative, and the project is abandoned on bad evidence.

Roughly half the corpus has no readable provenance marker. There is no way to recover it from the text. Only jhave knows.

---

## Inputs

- `corpus/survey.md`, section "Ambiguous — needs jhave" (from 1.1)
- `corpus/survey.json`

## Do not

- Infer provenance from prose style. Do not read a draft and judge whether it "sounds human." This is precisely the judgement the whole project is trying to learn, and using it as an input is circular.
- Infer from `edit-observations.md` presence. Its presence suggests an edit occurred somewhere nearby, not that this snapshot is the human one.
- Default unknowns to `machine`. Default them to `unknown` and exclude them.
- Batch questions in a way that invites a single blanket answer. Each ambiguous snapshot gets its own line.

---

## Method

1. **Pre-fill the unambiguous entries.** Snapshots classified `explicit-human` or `explicit-machine` in 1.1 are written directly to the ledger with `source: name-marker`. These need no confirmation.

2. **Build the question list.** For every snapshot classified `ambiguous-temporal`, `content-only` or `none`, produce one line:

   ```
   [ ] 09-05-2026_Slime / v1-2026-05-08-section-two  (2 drafts, 3,140 w)   machine | human | unknown
   ```

   Group by story, ordered by version. Keep it to one screen per story.

3. **Give jhave the list.** He marks each. Expect this to take a few minutes — he made these edits and will recognise them.

4. **Resolve the `ambiguous-temporal` cases explicitly.** For names like `v2-2026-06-08-before-human-style-propagation`, the question to ask is not "is this human?" but:

   > Is the human edit contained *in* this snapshot, or does it appear in the *next* one?

   Record the answer as `boundary: this` or `boundary: next`. This determines which side of the diff is the machine text.

5. **Write the ledger.** Every snapshot from 1.1 appears, including ones excluded from pairing.

---

## Output format

```yaml
# corpus/provenance.yaml
# Every snapshot in the corpus. The extractor reads only this file.

"01-07-2026_Cussinct/v3-2026-07-20-human-edit-pass":
  provenance: human
  source: name-marker          # name-marker | jhave | inferred-never
  boundary: this
  usable: true

"09-05-2026_Slime/v1-2026-05-08-section-two":
  provenance: machine
  source: jhave
  confirmed: 2026-08-06
  boundary: this
  usable: true

"20-06-2026_Project_A-0/v0":
  provenance: unknown
  source: jhave
  usable: false
  reason: metadata-only, no drafts/
```

Required fields: `provenance` (`machine` | `human` | `unknown`), `source`, `usable` (bool). Optional: `boundary`, `confirmed`, `reason`.

---

## Rules the extractor will apply to this file

State these in the ledger header so they are not re-derived later:

- A **pair** is emitted only for a transition where the earlier snapshot is `machine` and the later is `human`, both `usable: true`.
- `unknown` on either side → no pair. No exceptions.
- `human → human` → no pair. Consecutive human edits are one edit made in two sittings; the displacement is machine-relative or it is nothing.
- `machine → machine` → no pair.
- Where `boundary: next`, the snapshot's own text is the machine side even if the name mentions a human.

---

## Failure modes specific to this substep

- **Silent defaulting.** An agent that fills gaps with its best guess to produce a complete-looking file has destroyed the corpus and left no trace. `unknown` must survive to the output.
- **Blanket answers.** "All the Tamagotchi ones are machine" may be right, but confirm it story by story rather than accepting it as a pattern.
- **Losing the boundary question.** For `pre-`/`before-` names this is the entire question. Getting it backwards inverts every pair from that story.
- **Treating this as done when jhave has not answered.** If the list is unanswered, the substep is not complete. Say so; do not proceed to 1.3 on a provisional ledger.

---

## Acceptance criteria

- [ ] Every snapshot from `survey.json` appears in `provenance.yaml` exactly once
- [ ] No entry has `provenance: unknown` combined with `usable: true`
- [ ] Every `ambiguous-temporal` entry has an explicit `boundary` field
- [ ] Every entry with `source: jhave` has a `confirmed` date
- [ ] The count of emittable pairs under the rules above is stated at the top of the file
- [ ] No entry was assigned provenance by reading draft prose

## Report honestly

State the emittable pair count before any code is written. If it is under about 150, tell jhave — Step 2's test needs enough samples for a mean to be meaningful, and it is better to know that now than after building the extractor.
