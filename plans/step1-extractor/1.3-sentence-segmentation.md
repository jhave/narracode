# Substep 1.3 — Sentence segmentation

**Model: Opus 4.6.** Off-the-shelf tokenizers fail on this prose in ways that look like success.

**Output:** `tools/segment.py` and `tools/tests/test_segment.py`

May run in parallel with 1.2.

---

## Objective

Split literary prose into sentences, reliably enough that a diff between two versions aligns on real sentence boundaries rather than tokenizer artefacts.

---

## Why this exists

Every downstream number depends on sentence boundaries. Dimensions `d1` (length variation) and `d2` (adjacent jump) are computed directly from them. Alignment in 1.4 operates on the sentence list. A segmenter that splits `Mr.` into two sentences inflates the short-sentence count and corrupts `d1` in the direction the project is trying to measure.

The specific hazard: this corpus is deliberately full of fragments, subject-dropped verb chains, single-word sentences and unconventional punctuation, because those are the devices the registry adopted. A tokenizer trained on news text treats them as errors to be smoothed.

---

## Do not assume

- That NLTK `punkt` or spaCy handles this. Test before adopting.
- That a sentence ends at `. ! ?`. It also ends at a line break in fragment runs.
- That every capital letter after a period starts a sentence.
- That em-dashes and ellipses are sentence-internal. Sometimes they terminate.

---

## Cases that must be handled correctly

Build the test file from real corpus text, not invented examples. These are the categories:

| case | example | correct behaviour |
|---|---|---|
| single-word fragment run | `Counter. Grounds. The filter.` | 3 sentences |
| subject-dropped verb chain | `Emptied the drains into the compost. Rinsed the holder.` | 2 sentences |
| colon-apposition | `His own hands: chocolate.` | 1 sentence |
| parenthetical self-correction | `rolling boil froth (panic? no, calm.)` | 1 sentence — internal `?` and `.` do not split |
| em-dash appositive | `The queue — four and a diagonal — refilled.` | 1 sentence |
| dialogue with internal punctuation | `"Is it?" she said. "No."` | 2 or 3 — **decide, document, be consistent** |
| ellipsis mid-sentence | `He waited... then didn't.` | 1 sentence |
| abbreviation | `Mr. Kessler. 4 p.m. sharp.` | 2 sentences |
| numeric | `Two minutes forty.` | 1 sentence |
| line-break fragments | fragment run separated by newlines, no terminal punctuation | one per line |
| section marker | `§1`, `***`, `---` | not a sentence; excluded |

---

## Method

1. **Extract a test set from the real corpus.** Pull 200–300 sentences from at least five different stories, covering every case above. Store them in `tools/tests/segment_cases.md` with the expected segmentation written out by hand.

2. **Evaluate candidates against it.** At minimum: `nltk.punkt`, `spacy` sentencizer, `pysbd`, and a hand-written regex splitter. Report accuracy per case category, not just overall — a segmenter can score 95% overall and fail every fragment run.

3. **Choose, and document why.** If a library wins, use it with documented overrides for the failing categories. If the hand-written splitter wins, that is a legitimate result; this prose is unusual and 60 lines of explicit rules may beat a trained model.

4. **Make it deterministic and dependency-light.** It will run thousands of times across the corpus and again on every future edit. No model calls. No network.

5. **Handle the dialogue decision explicitly.** Whether `"Is it?" she said.` is one sentence or two changes `d1` measurably. Pick one, write it in a docstring, and never change it — changing it later silently invalidates every stored vector.

---

## Output

```python
def segment(text: str) -> list[str]:
    """Split prose into sentences.

    Decisions, fixed as of <date> — changing any of these invalidates
    every previously computed cadence vector:
      - dialogue tag attaches to the quoted sentence: '"Is it?" she said.' -> 1
      - line breaks terminate a sentence when no terminal punctuation present
      - parenthetical internal punctuation never splits
      - section markers are dropped, not returned as sentences
    """
```

Also emit a small report: `corpus/segmenter_eval.md`, with the per-category accuracy table for every candidate tested.

---

## Failure modes specific to this substep

- **Overall accuracy hiding categorical failure.** Always report per category. The fragment cases are the ones that matter and they are a small fraction of any test set.
- **Inventing test cases.** Expected outputs must be written by hand from real corpus text. A test set generated by the same model that wrote the segmenter tests nothing.
- **Silent normalisation.** Do not strip em-dashes, collapse whitespace inside sentences, or "fix" punctuation. The characters are the data.
- **Changing the decision later.** Any change to segmentation rules requires recomputing every vector in the corpus. Treat the docstring as a contract.

---

## Acceptance criteria

- [ ] `segment_cases.md` contains ≥200 hand-labelled sentences from ≥5 stories
- [ ] Every case category in the table above has ≥10 examples
- [ ] Per-category accuracy reported for every candidate evaluated
- [ ] Chosen segmenter scores ≥95% on every individual category, not merely overall
- [ ] Function is deterministic: same input, same output, no network, no model call
- [ ] Fixed decisions documented in the docstring

## Report honestly

If no candidate reaches 95% on the fragment categories, say so and report the best achieved. Do not adjust the test set to make a segmenter pass.
